> 📖 分类：**仓储** / 数据集成　｜　Message Queue = 消息队列

## 定义

Message Queue（消息队列，简称 MQ）是一种在分布式系统中用于实现应用程序之间异步通信的软件组件。在货运物流领域，它主要用于缓冲和可靠传输海量的单证、状态更新和报关指令，确保系统间解耦并防止流量过载。


## 详细说明

- 使用场景：广泛应用于国际货代系统的 EDI 数据交互、跨境电商订单同步、海关舱单申报状态回调、以及多式联运中各节点系统的数据对接。
- 关键规则或数字：遵循先进先出（FIFO）原则；企业级物流系统通常要求消息吞吐量达每秒数千条，消息持久化保存时间一般设定为 3-7 天，以应对系统宕机重试。
- 实务注意事项：在处理运单状态或财务数据时，必须确保消息处理的幂等性（Idempotency），防止因网络重试导致重复扣费或重复发送发货指令。

## 常见误区

- 误区一：认为消息队列只是简单的临时缓存。实际上，高可靠的物流消息队列具备持久化和死信队列（Dead Letter Queue）机制，能确保异常数据不丢失，便于人工介入排查。
- 误区二：认为所有物流系统交互都必须使用消息队列。对于需要实时同步的场景（如运费实时试算），直接调用 API 更合适，盲目引入消息队列会增加系统复杂度。
